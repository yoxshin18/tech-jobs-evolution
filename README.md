# Tech jobs evolution

**A perspective on the market's current state and what will change** — web-native interactive whitepaper, published on GitHub Pages.

🔗 **Online:** https://yoxshin18.github.io/tech-jobs-evolution/

Hybrid architecture: a **Python pipeline** transforms data extracted from reports into a static JSON; a **React (Vite) frontend** renders it as an interactive academic paper.

## Local Setup

```bash
# 1) data
pip install -r data-pipeline/requirements.txt
python data-pipeline/generate_data.py          # --check to validate without writing

# 2) frontend
cd web-paper
npm install
npm run dev                                    # http://localhost:5173
npm run build && npm run preview
```

`package-lock.json` is versioned: the workflow uses `npm ci` for reproducible builds.

## Deploy on GitHub Pages

1. In **Settings → Pages → Build and deployment**, choose **Source: GitHub Actions**.
2. Every push to `main` regenerates `market_data.json`, runs the build with `VITE_BASE=/<repo-name>/`, and publishes `web-paper/dist`.

## Languages (i18n)

The paper is available in full in **Italian, English, French, Spanish, and German**. The text lives exclusively in the `src/locales/*.json` files, managed by `i18next`; the language can be switched via the dropdown menu at the top right of the header.

To add a language: create `src/locales/<code>.json` with the same structure as `it.json`, import it in `src/i18n.js`, and add it to `LANGUAGES`. Missing keys fall back to Italian, so a translation can be completed in blocks: as long as the entry in `LANGUAGES` has `complete: false`, the paper displays a partial translation notice. The selected language is remembered and can be forced with `?lang=en`.

Structural elements must remain identical across locales, as they drive rendering and anchors: `sections[].id`/`number`/`navKey`, block `type` and `id` values, figure `chart` keys, `emerging`/`scenarios` `id`s, and reference `id`/`year`/`url` fields. Citation markers (`[3]`, `[1, 2]`, `[11–17]`) and `**bold**` / `*italic*` / `` `code` `` markup must also be preserved. Numbers in charts are formatted via `Intl.NumberFormat` using the active locale, while those in the body text follow the conventions of the specific language.

The body of the paper is described as a list of **blocks** (`p`, `h3`, `list`, `callout`, `kpis`, `figure`, `roleCards`, `roleTable`, `emerging`, `scenarios`, `references`, `cite`). Within the text, `**bold**`, `*italic*`, `` `code` ``, and citations `[3]`, `[1, 2]`, `[11–17]` are supported, turning into interactive links with a reference preview.

## Data and Methodology

- **Reported data vs. estimate.** Every value in `raw/` has a `source_id`; the pipeline marks calculated values as `derived` (CAGR, logistic curves, AI penetration index, radar normalizations). Figures containing estimates feature the *Author's estimate* tag.
- **AI adoption projection.** Logistic curve with fixed capacity K (0.87 / 0.92 / 0.97), estimated via OLS on the logit of Stack Overflow 2023–2026 shares.
- **AI penetration index.** Σ weight(role, task) × AI usage share per task (SO 2026). Weights are stored in `role_task_weights.csv`: modifying them and re-running the pipeline updates both figures and tables.
- **Declared BLS proxies.** AI/ML Engineer → Computer and Information Research Scientists; Data Engineer → Database Architects; MLOps/Cloud → Computer Network Architects.
